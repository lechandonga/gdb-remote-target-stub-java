# gdb-remote-target-stub-java

一个纯 Java 实现的 GDB 远程调试目标端（stub）。它在本地 TCP 端口上讲
GDB 远程串行协议（Remote Serial Protocol, RSP），背后用一块**模拟的嵌入式
板子**代替真实硬件，GDB 连上后可以读寄存器、读写内存、下断点、继续、单步，
并拿到正确的停止原因。

## 运行

```bash
mvn spring-boot:run                 # 默认监听 5000 端口
mvn spring-boot:run -Dspring-boot.run.jvmArguments=-Dstub.port=5001
```

GDB 侧连接：

```
(gdb) target remote localhost:5000
```

## 架构

| 类 | 职责 |
| --- | --- |
| `gdb/GdbStubServer.java` | TCP 监听，单会话仲裁，拒绝并发连接 |
| `gdb/GdbSession.java` | RSP 包层（封帧/校验/转义/ACK/重传）+ 命令分发 |
| `target/TargetMachine.java` | 模拟目标板：寄存器、内存、指令集、断点、执行 |

## 协议子集

### 包层

- 帧格式 `$payload#cc`，校验和为未转义载荷字节和的最低 8 位（两位十六进制）。
- 转义：`0x7D`（`}`）后跟 `字节 ^ 0x20`；发送侧转义 `$ # } *`。
- 确认：默认每个合法包回 `+`；校验错误、非十六进制校验位、帧内出现新的 `$`
  （视为前一包被截断）都回 `-` 并丢弃，**不污染后续交互**；收到 `-` 会重传上一条回复。
- 无确认模式：`QStartNoAckMode` 协商成功后不再发送 `+`。
- 运行中收到 `0x03`（Ctrl-C）会中断目标并以 `S02` 停止。
- 语法合法但不支持的命令一律返回空响应 `$#00`。

### 支持的命令

| 命令 | 语义 |
| --- | --- |
| `?` | 当前停止原因 |
| `qSupported` | 能力协商（固定回复，不随连接顺序/重试漂移） |
| `QStartNoAckMode` | 进入无确认模式 |
| `qAttached` / `qC` / `qfThreadInfo` / `qsThreadInfo` | 固定单线程模型 |
| `g` / `G` | 读/写全部寄存器 |
| `p n` / `P n=v` | 读/写单个寄存器 |
| `m a,l` / `M a,l:data` | 读/写内存 |
| `Z0/z0` | 插/删软件断点（最多 32 个） |
| `Z1/z1` | 插/删硬件断点（最多 4 个） |
| `s` | 单步 |
| `c` | 继续 |
| `k` | 复位目标（寄存器清零、回到 STOPPED；内存与断点保留） |
| `H*` | 线程选择，固定回 `OK` |

### 停止回复

| 回复 | 含义 |
| --- | --- |
| `S05` | 断点命中 / 单步完成 / BKPT 指令 |
| `W00` | 程序执行到 HALT，正常结束 |
| `S0B` | 执行中访问未映射内存（SIGSEGV） |
| `S02` | 被 Ctrl-C 中断（SIGINT） |
| `S11` | 指令预算耗尽（防死循环兜底） |

### 错误回复

| 回复 | 含义 |
| --- | --- |
| `E01` | 访问未映射内存（`m`/`M` 越界） |
| `E02` | 断点数量超限 |
| `E03` | 非法状态下发起运行（目标已在运行或已 EXITED） |
| `E04` | 命令参数格式错误 |

## 目标模型

- 寄存器：10 个 32 位寄存器，顺序 `r0..r7, pc(8), sp(9)`；
  `g`/`G` 包中每个寄存器 4 字节小端十六进制。
- 内存：64 KiB RAM，映射在 `0x0000..0xFFFF`，其余地址为未映射。
- 指令：定长 4 字节小端。

| 编码 | 指令 | 语义 |
| --- | --- | --- |
| `00 00 00 00` | HALT | 程序结束（`W00`） |
| `01 00 00 00` | NOP | 空操作 |
| `02 rd rs 00` | ADD | `rd += rs` |
| `03 rd lo hi` | MOVI | `rd = imm16` |
| `04 rd rs 00` | LOAD | `rd = mem32[rs]` |
| `05 rd rs 00` | STORE | `mem32[rd] = rs` |
| `06 00 00 00` | BKPT | 软件断点自陷（`S05`） |
| `07 lo hi 00` | JMP | `pc = imm16` |
| `08 rs lo hi` | JNZ | `rs != 0` 时 `pc = imm16` |

执行语义：从断点继续时先单步越过当前 pc 上的断点再重新检查；取指或
LOAD/STORE 越界会产生 `S0B` 停止；单次继续有 1000 万条指令的预算兜底。

## 会话与状态语义

- **单会话**：同一时间只允许一个调试会话；多余连接会收到一行明文
  `E:stub busy, another debug session is active` 后被关闭。
- **可重连**：断开后允许新会话接入。
- **状态保留规则**：目标板只有一块且由服务器持有——内存、寄存器、断点
  **跨会话保留**（相当于板子一直上电）；只有 `k`（复位寄存器）或重启
  服务器进程才会改变状态。能力协商结果是常量，与连接顺序、重试无关。

## 本地验证

```bash
mvn test
```

测试用本地回环的假 GDB 客户端（`tests/gdb/FakeGdbClient`）驱动真实 stub，
日志中每个场景都有 `=== SCENARIO ===` / `--- PASS ---` 标记，覆盖：

- 校验错误 → NAK → 重传被正常接收
- 帧内出现新 `$`（截断包）→ NAK 且后续包不受污染
- 转义字节的解码与校验
- 不支持命令返回空响应
- 无确认模式协商与能力稳定性
- 寄存器（`g/G/p/P`）与内存（`m/M`）读写
- 未映射内存访问被拒（`E01`）
- 软件断点命中、继续到程序结束（`S05`/`W00`）
- 硬件断点数量上限（`E02`）
- 单步语义
- 程序结束后继续运行被拒（`E03`）与 `k` 复位
- Ctrl-C 中断运行中的程序（`S02`）
- 断连重连后断点/内存保留、能力不漂移
- 并发会话被拒并说明原因
- 不完整包 + 异常断连不影响下一个会话
