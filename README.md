# GDB Remote Target Stub（Java 模拟嵌入式板子）

本工程在本地回环上实现了一个 **GDB 远程串行协议（RSP）目标端 stub**：
后端不是真实硬件，而是一块用 Java 模拟的 16 位地址空间嵌入式小板子。
用真正的 `gdb`（或测试里的假 GDB 客户端）通过 TCP 连上来后，可以完成
读寄存器、读写内存、软件/硬件断点、继续、单步，并拿到正确的停止原因。

## 运行

```bash
mvn spring-boot:run            # 默认监听 2345
# 或
java -jar target/gdb-remote-target-stub-java-1.0-SNAPSHOT.jar --gdbstub.port=2345

gdb
(gdb) target remote :2345
```

测试使用随机临时端口（`gdbstub.port=0`）且不启动 Web 容器
（`spring.main.web-application-type=none`）。

## 模拟目标模型

### 地址空间与内存

| 范围 | 区域 | 调试访问（m/M/X） | 模拟指令 STORE |
| --- | --- | --- | --- |
| `0x0000–0x7FFF` | 代码/Flash | 可读可写 | 写入触发 SIGSEGV |
| `0x8000–0xFFFF` | RAM | 可读可写 | 可读可写 |
| 超出 `0xFFFF` / 跨边界 | 未映射 | `E10` | — |

共 64 KiB，统一编址。越界或跨过 64 KiB 边界的访问一律被拒绝，不产生部分写入。

### 寄存器（9 个，32 位，小端）

| 索引 | 名称 | 说明 |
| --- | --- | --- |
| 0–7 | `g0..g7` | 通用寄存器 |
| 8 | `pc` | 程序计数器 |

`g`/`G` 整体读写按小端字节序；`p`/`P` 读写单个寄存器。
非法寄存器编号返回 `E01`。stub 通过 `qXfer:features:read:target.xml`
向 GDB 描述同一套寄存器布局。

### 指令集（32 位定长，小端，4 字节对齐）

指令字 = `opcode:8 | op1:8 | operand:16`。

| opcode | 汇编 | 语义 |
| --- | --- | --- |
| `0x00` | `NOP` | 空操作 |
| `0x01` | `HALT imm8` | 程序结束，退出码为立即数（停止回复 `Wxx`） |
| `0x02` | `MOVI g[op1], imm16` | 16 位立即数零扩展写入寄存器 |
| `0x03` | `ADD g[op1], g[imm&7]` | 寄存器加 |
| `0x04` | `LOAD g[op1] = u16[imm16]` | 从内存读 16 位（小端） |
| `0x05` | `STORE u16[imm16] = g[op1]` | 写 16 位；地址在 Flash 区时 SIGSEGV |
| `0x06` | `JMP imm16` | 无条件跳转 |
| `0x07` | `JZ g[op1], imm16` | 寄存器为 0 则跳转 |
| 其他 | — | 非法指令，SIGILL（`S04`） |

`pc` 非对齐执行、跑到地址空间外同样以 SIGSEGV（`S0b`）停止。

## 支持的协议子集

### 封帧、校验、转义、确认

- 数据包格式 `$payload#cc`，`cc` 为 data 段字节和模 256 的两位小写十六进制。
- 支持二进制转义：`# $ } * 0x03 0x7d 0x7f` 发送为 `}` + 字节异或 `0x20`；
  接收端在识别包结束符 `#` **之前**逐字节处理转义引导符，因此数据段中
  出现的 `#`/`$` 不会破坏帧边界。
- 默认确认模式：正确收到包回 `+`；校验和不符回 `-`，由对端重传。
  起始标记前的噪声字节被静默丢弃；校验位损坏无法恢复时重新同步到下一个
  `$`；不完整输入（缺少 `#cc`）持续等待后续字节，不会污染之后的交互。
- 发送端在确认模式下等待 `+`，1 秒超时重传，最多 3 次，之后判定连接失效。
- 支持 `QStartNoAckMode`：协商成功后双方均不再收发 `+/-`。
  无确认模式是**每连接属性**，断开重连后恢复为确认模式。

### 命令

| 命令 | 含义 |
| --- | --- |
| `?` | 查询最近停止原因（`Sxx` / `Wxx`） |
| `g` `G` | 读/写全部寄存器（小端 hex） |
| `p n` `P n=v` | 读/写单个寄存器 |
| `m a,l` `M a,l:hex` | 读/写内存（hex） |
| `X a,l:<binary>` | 二进制写内存 |
| `c [addr]` `s [addr]` | 继续 / 单步 |
| `Z0,z0,a,k` | 软件断点（最多 4 个） |
| `Z1,z1,a,k` | 硬件执行断点（最多 2 个） |
| `D` | 分离：回复 `OK` 后关闭 TCP 连接 |
| `k` | kill：复位板子并关闭连接 |
| `R00` | 复位目标（内存、寄存器、断点全部清空），会话保留 |
| `qSupported` | 能力：`PacketSize=1000;QStartNoAckMode+;qXfer:features:read+` |
| `qAttached` `qC` `qfThreadInfo` `qsThreadInfo` `qOffsets` | 单线程/附着相关固定回复 |
| `qXfer:features:read:target.xml:off,len` | 目标描述（分片，`m`/`l` 前缀） |
| `H`/`h` | 线程选择（单线程目标，回 `OK`） |
| `vCont?` | `vCont;s;c` |
| `vKill` | 复位目标 |
| `0x03`（Ctrl-C） | 运行中中断，停止回复 `S02`（SIGINT） |

**语法合法但当前不支持的命令一律返回空响应**（空 payload），
例如 `vMustReplyEmpty`、`qTStatus`、观察点 `Z2,...`、其它 `Q*` 包。

### 停止回复

| 场景 | 回复 |
| --- | --- |
| 单步完成 | `S05`（SIGTRAP） |
| 断点命中（继续运行时） | `S05`，pc 停在断点地址 |
| Ctrl-C 中断 | `S02`（SIGINT） |
| 非法指令 | `S04`（SIGILL） |
| pc 越界/非对齐、STORE 写 Flash | `S0b`（SIGSEGV） |
| 程序执行 `HALT` | `Wxx`（退出码），之后 `?` 仍回 `Wxx` |

单步不触发断点（与 GDB “临时摘除断点再 step” 的语义一致）；
继续运行每取一条指令前检查软件与硬件断点集合。
断点为地址集合模拟，**不改动内存内容**（`m` 读到的始终是真实字节）。

### 错误回复

| 回复 | 含义 | 触发示例 |
| --- | --- | --- |
| `E01` | 非法寄存器编号 | `p9` |
| `E05` | 非法运行状态 | 程序已退出后再次 `c`/`s`；目标已在运行 |
| `E10` | 访问未映射内存 | `mfffe,4`、跨越 64 KiB 的写 |
| `E13` | 断点资源超限 | 第 5 个 `Z0`、第 3 个 `Z1` |
| `E14` | 断点地址非法 | RAM 里的软件断点、非 4 字节对齐地址 |
| `E22` | 参数错误 | `G` 长度不足、`X` 数据截断 |

错误都是正常协议回复（`$Exx#cc`），不会导致会话崩溃或挂死。
第二连接的拒绝发生在协议层之外（见下），使用纯文本：
`ERR:E80:debug session already in use from <peer>`，随后关闭连接。

## 会话语义

- **单会话**：同一时间只接受一个调试连接；多余连接立刻收到上述 `E80`
  拒绝说明并被关闭，不会排队、不会影响现有会话。
- **重连保留状态**：普通 TCP 断开（或 `D` 分离）后槽位立即释放；
  内存、寄存器、软件/硬件断点、停止状态在重连之间保留。
- **复位规则**：只有 `k`、`vKill`、`R00` 会清空板子状态；
  普通断连不清空。
- **能力稳定**：`qSupported`、`qXfer` 等协商结果是固定常量，
  不随连接顺序、重连或重试漂移；`QStartNoAckMode` 不跨连接泄漏。
- **断连中止运行**：运行中对端关闭连接，stub 会终止当前运行循环并释放会话。

## 本地验证

```bash
mvn test
```

测试全部由回环上的假 GDB 客户端驱动（`FakeGdbClient`，手工封帧，
可精确制造坏校验和、噪声、半包、转义二进制、0x03 中断等），
按业务分为五类：

- `ProtocolFramingTest` —— 封帧往返、坏校验和 `-`/重传、起始噪声、
  半包补全、无确认模式、能力稳定性、不支持命令空响应
- `RegisterMemoryTest` —— 单/整体寄存器读写、`m/M/X`（含转义字节）、
  非法寄存器与未映射内存
- `ExecutionBreakpointTest` —— 单步、软件/硬件断点命中与上限、
  单步不触发断点、`HALT` 退出、退出后运行拒绝、Ctrl-C、SIGILL、SIGSEGV
- `SessionLifecycleTest` —— 并发会话 `E80` 拒绝、断连重连状态保留、
  `D` 释放槽位、`R00` 复位、能力与无确认模式不跨连接漂移

运行日志通过 `BusinessLoggingListener` 按业务逐条输出，例如：

```
INFO [BUSINESS-COVERAGE] [业务:ProtocolFramingTest] 用例 PASS :: 坏校验和：...
```

因此从 `mvn test` 输出即可看出覆盖了哪些业务、每个业务有哪些用例及其结果
（PASS/FAIL/ABORTED/DISABLED）。
